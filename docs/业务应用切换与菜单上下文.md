# 业务应用切换与菜单上下文

## 当前结论与目标

SaaS 与项目运行态前端左上角标题作为业务应用切换入口。可选项来自 `GET /business-application/me`；进入业务应用时，应用运行态的 project storage 会写入 `scope: <applicationId>`，`package.ts` 请求拦截器据此为该应用下所有接口携带 `X-Application-Scope: <applicationId>`。项目本身不写入 `scope`，因此项目接口不携带应用 Scope。

应用选择保存在当前浏览器标签页的 `sessionStorage` 中，应用运行态的接口 Scope 保存在对应 `project_<applicationId>` 的 project storage 中。运行边界统一通过 `src/utils/business-application-runtime.ts` 判断：非微应用下的 SaaS 端与项目运行态都会初始化应用列表，因此独立项目端即使 `VITE_APP_ENVIRONMENT=''` 也会请求 `/business-application/me`。项目运行态在没有显式 `applicationScope` 时默认保留项目菜单；子账号登录成功后会主动查询应用列表，并通过同一套“进入应用”逻辑进入第一个业务应用。若当前账号没有业务应用，则继续走原项目入口逻辑。

当业务应用列表非空时，下拉中会附加一个项目入口。该入口使用项目菜单请求，不写入 storage scope，用于从业务应用切回项目本身。

## 影响范围与 owning module

owning module：`ui/jetlinks-web-core`；子账号登录入口位于 `ui/modules/saas-manager-ui`。

- `src/api/application.ts`：业务应用类型和 `/business-application/me` 请求。
- `src/store/businessApplication.ts`：应用列表、当前应用、初始化和切换编排。
- `src/utils/business-application-runtime.ts`：统一判断 SaaS 与项目运行态是否启用应用切换。
- `src/utils/application-scope.ts`：标签页级 Scope 读取、选择和持久化。
- `src/utils/application-access.ts`：生成应用入口 URL；project storage 关闭的独立项目端仅支持同源切换，不写入 `project_<applicationId>`。
- `src/utils/project-storage.ts`：保留 `projectName`，避免切入业务应用后丢失项目下拉名称。
- `src/package.ts`：请求拦截器从当前 project storage 读取 `scope`，存在时为 axios 与 NDJSON 请求补充 `X-Application-Scope`。
- `src/store/menu.ts`、`src/store/menuRuntime.ts`：按应用重载菜单，替换旧动态路由和按钮权限，返回首菜单。
- `src/router/startup.ts`、`src/router/index.ts`：登录会话先初始化应用，无可进入应用时进入 403。
- `src/layout/components/BusinessApplicationSwitcher.vue`、`BusinessApplicationIcon.vue`、`src/layout/BasicLayoutPage.vue`：复用现有标题位和 Ant Design Vue Dropdown/Menu 实现切换入口。
- `../modules/saas-manager-ui/views/login/components/SubAccountLogin.vue`：子账号登录后先保存项目访问上下文，再进入首个业务应用；没有业务应用时回到原项目跳转。

## 实施边界

- 不修改 `runtime-ui/`。
- 不修改后端接口契约。
- 不为项目本身写入 `scope`，只让业务应用运行态携带 `X-Application-Scope`。
- 菜单请求失败时保留原应用、原菜单、权限和当前路由。
- 不改业务页面壳层、菜单模型或普通业务接口请求上下文。

## 风险与验证方式

- 切换应用时必须卸载上一轮服务端动态路由，避免旧应用独有路由继续可达。
- 快速或并发菜单请求只允许最后一次响应提交路由和权限。
- 子账号登录无业务应用时回到原项目入口；业务应用无菜单时按进入应用逻辑落到 `/403`。
- 静态验证包括 JSON 解析、Vue/TS 语法转换、`git diff --check`、Scope 聚焦测试和 Header 边界搜索；真实接口与视觉交互需在登录态浏览器中冒烟。
