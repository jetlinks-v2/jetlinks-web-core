# 业务应用切换与菜单上下文

## 当前结论与目标

SaaS 运行时前端左上角标题作为业务应用切换入口。可选项来自 `GET /business-application/me`；当前应用确定后，仅菜单请求 `POST /menu/user-own/tree` 携带 `X-Application-Scope: <applicationId>`，按该应用重新构建菜单、按钮权限和动态路由，并重定向到第一个可访问菜单。

应用选择保存在当前浏览器标签页的 `sessionStorage` 中；普通业务接口不携带该 Scope。运行边界使用 `VITE_APP_ENVIRONMENT=saas`，不依赖 URL 是否包含项目 code，因此本地根路径开发环境也会初始化应用列表。

## 影响范围与 owning module

owning module：`D:/Work/jetlinks2/saas-runtime-ui/jetlinks-web-core`。

- `src/api/application.ts`：业务应用类型和 `/business-application/me` 请求。
- `src/store/businessApplication.ts`：应用列表、当前应用、初始化和切换编排。
- `src/utils/application-scope.ts`：标签页级 Scope 读取、选择和持久化。
- `src/store/menu.ts`、`src/store/menuRuntime.ts`：按应用重载菜单，替换旧动态路由和按钮权限，返回首菜单。
- `src/router/startup.ts`、`src/router/index.ts`：登录会话先初始化应用，无可进入应用时进入 403。
- `src/layout/components/BusinessApplicationSwitcher.vue`、`BusinessApplicationIcon.vue`、`src/layout/BasicLayoutPage.vue`：复用现有标题位和 Ant Design Vue Dropdown/Menu 实现切换入口。

## 实施边界

- 不修改运营端 `ui/`。
- 不修改后端接口契约。
- 不把 `X-Application-Scope` 注册成全局请求头。
- 菜单请求失败时保留原应用、原菜单、权限和当前路由。
- 不执行 `build`、`vue-tsc` 或 `tsc`。

## 风险与验证方式

- 切换应用时必须卸载上一轮服务端动态路由，避免旧应用独有路由继续可达。
- 快速或并发菜单请求只允许最后一次响应提交路由和权限。
- 无应用或应用无菜单进入 `/403`；正常切换使用 `router.replace` 进入首菜单。
- 静态验证包括 JSON 解析、Vue/TS 语法转换、`git diff --check`、Scope 聚焦测试和 Header 边界搜索；真实接口与视觉交互需在登录态浏览器中冒烟。
