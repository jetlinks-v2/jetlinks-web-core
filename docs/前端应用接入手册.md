# 前端应用接入手册

> 范围：`runtime-ui/`（运行时前端）　｜　对象：写页面的后端开发、初级前端
>
> 讲五件事：**子模块结构 → 构建子模块 → 内置接入 → 微前端接入 → 自定义样式与布局**

## 准备工作

### 代码

```bash
cd runtime-ui
pnpm modules:init     # 拉取子模块，并切到与主仓库同名的分支
ls jetlinks-web-core/src modules/     # 确认不是空目录
pnpm install
```

子模块没拉全就 `pnpm install`，会出现依赖缺失、菜单缺失、页面打不开。

### 仅微前端额外需要

| 项 | 用途 |
| --- | --- |
| JDK + Maven，能访问 JetLinks Maven 仓库 | 把模块打成 jar（第 4.2 步 ④） |
| Docker | 走 Maven 的 `-P ui-package` 时，构建在 `jetlinks-template-ui` 镜像里执行；本地直接 `pnpm build:modules` 不需要 |
| 一个会引入该 jar 的后端服务 | 部署后由 `/system/resources/ui` 对外发现 |

---

## 0. 两种接入方式

| | 内置接入 | 微前端接入 |
| --- | --- | --- |
| 代码位置 | `runtime-ui/modules/<name>-ui/` | 同左（同一套子模块结构） |
| 如何被宿主加载 | 宿主构建时扫描 `modules/*/index.ts`，打进同一个包 | 子模块单独构建、随后端 jar 发布；宿主运行时按 `/system/resources/ui` 发现并加载 |
| 页面运行在哪 | 宿主 Vue 应用内 | micro-app 子应用（iframe 沙箱）内 |
| 发布 | 跟随 `runtime-ui` 整体发版 | 模块单独发版，宿主不用重新构建 |
| 什么时候用 | **默认选这个** | 模块需要独立发版 / 按部署选装 |

**先按内置接入把页面做通，再决定要不要切微前端。** 两者的子模块代码结构完全一样，差别只在构建和发布。

## 1. 子模块结构

### 1.1 目录

```text
runtime-ui/modules/training-app-ui/
├── package.json         ★ 模块身份：name / id
├── index.ts             ★ 模块入口：宿主唯一的发现入口，必须 export default
├── baseMenu.json        ★ 菜单定义（和 baseMenu.ts 成对出现）
├── baseMenu.ts          ★ 菜单导出
├── register.ts          ☆ 对外公开的 apis / components；微前端的远程入口
├── tsconfig.json        ☆ 类型检查
├── pom.xml              ☆ 仅微前端：打进后端 jar
├── api/                 接口封装
├── hooks/               状态与流程
├── components/          模块内组件
├── views/               路由页面：views/<code>/index.vue
├── shells/              可选：自定义应用外壳
└── locales/lang/        zh.json / en.json / ja.json
```

★ 必须　☆ 按需

### 1.2 命名约定（三处必须对齐）

| 位置 | 示例 | 规则 |
| --- | --- | --- |
| 目录名 | `training-app-ui` | `<id>-ui` |
| `package.json` → `name` | `training-app-ui` | 等于目录名；同时生成别名 `@training-app-ui/*` |
| `package.json` → `id` | `training-app` | 模块 ID；写进菜单 `options.appName`；微前端时等于后端 UI 资源 ID |

### 1.3 `index.ts` 能导出什么

| 导出 | 作用 | 用不用 |
| --- | --- | --- |
| `getAsyncRoutesMap()` | 页面映射：`views/a/B/index.vue` → `a/B` | **必须** |
| `getExtraRoutesMap()` | 非菜单路由（详情页、编辑页） | 常用 |
| `register()` | 把 `register.ts` 注册到 `moduleRegistry`，供其他模块调用 | 有对外能力时 |
| `priority` | 模块排序 / 外壳冲突时的优先级，大者胜 | 按需 |
| `filter: true` | 让宿主忽略整个模块 | 临时下线 |
| `getContentPanelOverrides()` | 控制页面是否套统一内容面板（见 5.2） | 按需 |
| `getApplicationShell()` | 声明应用自带外壳（见 5.3） | 按需 |
| `getRegisterComponents()` | 往其他页面/布局的扩展点插组件 | 按需 |
| `getCoreRouteOverrides()` | 覆盖宿主核心路由（如登录页） | 慎用 |

完整类型：[types/module.ts](../src/types/module.ts)。

`baseMenu.ts`

```ts
import baseMenu from './baseMenu.json'
import packageInfo from './package.json'
import type { MenuItem } from '@jetlinks-web-core/types/module'

const withModuleOptions = (menus: MenuItem[]): MenuItem[] => menus.map(item => ({
  ...item,
  children: item.children ? withModuleOptions(item.children) : undefined,
  options: { appName: packageInfo.id || packageInfo.name, ...item.options },
  runtime: true,
}))

export default () => withModuleOptions(baseMenu as MenuItem[])
```

| 字段 | 填什么 | 填错的后果 |
| --- | --- | --- |
| `code` | 页面映射键，= `views/` 下的路径 | 大小写不一致 → 空白 / 404 |
| `url` | 浏览器地址 | — |
| `owner` | 应用端固定 `app`，每层都写 | 写成别的 → 应用里没有这个菜单 |
| `showPage` | 后端权限资源 ID | 不写或写错 → 菜单设置里看不到候选 |
| `permissions` | 菜单授予的后端资源 + 操作 | 漏写 → 接口 403 |
| `assetTypes` | 后端资产类型 ID | 按名字猜 → 数据权限配置不到 |
| `options.appName` | 模块 `id`（`baseMenu.ts` 自动填） | 手写成应用实例 ID |

### 2.5 接口 `api/workorders.ts`

```ts
import { request } from '@jetlinks-web/core'
import type { AxiosResponseRewrite } from '@jetlinks-web/types'

export interface WorkOrder {
  id: string
  name: string
  status: { value: string; text: string }
}

export interface WorkOrderPage {
  data: WorkOrder[]
  total: number
}

const WORK_ORDERS_PATH = '/inspection/workorders/_query'

export const queryWorkOrders = (): Promise<AxiosResponseRewrite<WorkOrderPage>> =>
  request.post(WORK_ORDERS_PATH, {
    pageIndex: 0,
    pageSize: 10,
    sorts: [{ name: 'createTime', order: 'desc' }],
  })
```

**只用宿主 `request`**：它已处理 Token、API 前缀、应用范围头 `X-Asset-Scope`。页面里不手拼 Token、域名、范围头，也不新建 axios。

### 2.6 状态 `hooks/useWorkOrders.ts`

```ts
import { onScopeDispose, ref, watch } from 'vue'
import { useRoute } from 'vue-router'
import { queryWorkOrders, type WorkOrder } from '../api/workorders'

export function useWorkOrders() {
  const route = useRoute()
  const rows = ref<WorkOrder[]>([])
  const total = ref(0)
  const loading = ref(false)
  const failed = ref(false)
  let requestId = 0

  async function reload() {
    const current = ++requestId
    loading.value = true
    failed.value = false
    rows.value = []
    total.value = 0
    try {
      const response = await queryWorkOrders()
      if (current !== requestId) return            // 丢弃迟到响应
      if (!response.success || !response.result) throw new Error('query failed')
      rows.value = response.result.data
      total.value = response.result.total
    } catch {
      if (current === requestId) failed.value = true
    } finally {
      if (current === requestId) loading.value = false
    }
  }

  // 切换应用 / 地址时重查，旧数据不能串到新范围
  watch(() => route.fullPath, reload, { immediate: true })
  onScopeDispose(() => { requestId++ })
  return { rows, total, loading, failed, reload }
}
```

## 3. 内置接入 runtime-ui

### 3.1 本地跑起来

```bash
cd runtime-ui
pnpm install                                   # 新建模块后必须重新执行
pnpm dev:proxy localhost:8844                  # 全量模块，换成实际后端地址
```

只调自己的模块，启动更快：

```bash
pnpm -F jetlinks-web-core dev -- --module-name training-app-ui
pnpm -F jetlinks-web-core dev -- --module-name training-app-ui,device-manager-ui   # 联调时带上要调用的模块
```

`--module-name` 是**白名单**，填目录名：没列出的模块会被替换为空文件。要联调其他模块通过 `moduleRegistry` 提供的能力，就把那些模块一起列上。报 `xxx is not exported` 说明你直接 `import` 了别的模块，改走 `moduleRegistry`，不要靠加白名单绕过。

### 3.2 让页面出现在应用里

| # | 操作 | 要点 |
| --- | --- | --- |
| 1 | 进入初始化页面，点击“保存” | `baseMenu.json` 不会自动同步，改了要重新做这步 |
| 2 | 应用模版：新建内置业务应用模板 → 勾选菜单和权限 → 启用 | 内置模板不填回调地址、通知地址、密钥 |
| 3 | 应用管理：用模板建实例 → 启用 | 一个模板可建多个应用，代码只有一份 |
| 4 | 实例内建角色 → 授予菜单 → 测试用户入应用并分配角色 | 只入应用不分配角色，看不到菜单 |
| 5 | 普通账号从应用列表打开实例 | 不要只用 admin 验证 |

**⚠️ 不要单独调 `PATCH /menu/app/_all` 推菜单**：按 owner 整棵替换，会清掉现有菜单。

### 3.3 联调看 Network

| 看什么 | 正常 | 不正常先查 |
| --- | --- | --- |
| `/menu/user-own/tree` | 包含 `training/WorkOrders` | owner、菜单同步、角色授权 |
| 页面 | 点菜单出页面 | `code` ↔ `views/` 路径大小写 |
| 业务请求 | 正确路径 + 请求头 `X-Asset-Scope: business_application:<实例ID>` | 是否绕过了宿主 `request` |
| 响应 | `result.data` 为数组 | 响应层级取错 |

## 4. 微前端接入

### 4.1 当前机制

```text
 构建                     发布                              宿主运行时
 ──────────────────      ──────────────────────────       ─────────────────────────────────────────
 pnpm build:modules  →   pom.xml 打包进后端 jar        →   GET /system/resources/ui 拿到 {id, path}
   modules/x-ui/dist/      classpath:/ui/<id>/               ├─ 本地没有 <id>-ui 模块
   ├─ index.html           ├─ package.json                   │    → 加载 <path>/assets/remoteEntry.js
   ├─ assets/              ├─ baseMenu.json                  │      注册 register.ts 的 apis/components
   │  └─ remoteEntry.js    └─ index.html + assets/            └─ 菜单 options.appName = <id>
   └─ baseMenu.json                                               → micro-app 加载 <path>/index.html?layout=false
```

- **页面**：菜单叶子节点由 micro-app 子应用渲染（`VITE_MICRO_APP=true` 时开启，各 `.env` 默认开启）。子应用就是"只含本模块的 runtime-ui"，`layout=false` 隐藏子应用自己的布局。
- **公开能力**：`register.ts` 被打成 `remoteEntry.js`，宿主和其他模块照常通过 `moduleRegistry` 调用。
- **菜单**：初始化菜单时宿主读取 `<path>/baseMenu.json` 合并候选。
- **开发环境**：`import.meta.env.DEV` 下如果本地 `modules/` 已有该页面，优先用本地页面，不走子应用。

### 4.2 步骤

**① 对齐三个 ID**：目录 `<id>-ui`、`package.json` 的 `id`、`pom.xml` 的 `artifactId` 三者一致（本例 `training-app`）。后端用 `artifactId` 作为发布目录 `ui/<artifactId>/`，宿主用 `<id>-ui` 判断本地是否已有该模块。

**② 本地开发、测试**：

```bash
cd runtime-ui
pnpm micro          # 交互式选择要启动的子模块
```

打包前怎么测，见 4.3。

**③ 单独构建**：

```bash
pnpm build:modules training-app-ui
# 产物：modules/training-app-ui/dist/（含 index.html、assets/remoteEntry.js、baseMenu.json）
```

**④ 打进后端 jar**：照抄 `runtime-ui/modules/jetlinks-function-ui/pom.xml`，改 `artifactId` / `name`。默认构建把 `package.json`、`baseMenu.json` 放到 `ui/<artifactId>/`；`-P ui-package` 时再把 `dist/` 一起打进去。

**⑤ 后端服务引入该 jar** → 部署后 `GET /system/resources/ui` 应返回 `{ id: "training-app", path: "ui/training-app" }`。

**⑥ 同 3.2 做菜单同步、模板、实例、授权。**

### 4.3 未打包时如何测试

打包部署前，模块直接在本地 dev 里跑：**开发环境下，宿主发现本地 `modules/` 里有这个页面，就用本地代码渲染**，不走 micro-app 子应用，也不加载 `remoteEntry.js`。所以页面开发和联调跟内置模块完全一样。

```bash
cd runtime-ui
pnpm -F jetlinks-web-core dev -- --module-name training-app-ui --backend-url <后端地址>
# 或 pnpm micro --backend-url <后端地址>，交互式选择模块
```

| 测什么 | 怎么测 |
| --- | --- |
| 页面、接口、交互 | 按上面启动，从应用入口进入页面 |
| 菜单 | 本地 `baseMenu.json` 会合并进菜单设置的候选。要在本地同步菜单，把菜单管理所在模块一起带上：`--module-name training-app-ui,authentication-manager-ui` |
| 子应用里的显示效果 | 页面地址加 `layout=false`（如 `#/training/workorders?layout=false`），宿主布局隐藏，只剩页面内容，跟子应用里看到的一致 |
| `register.ts` 公开的能力 | 调用方模块和本模块一起加进 `--module-name`，确认通过 `moduleRegistry` 取得到 |
| 构建产物 | `pnpm build:modules training-app-ui`，检查 `dist/` 里有 `index.html`、`assets/remoteEntry.js`、`baseMenu.json` |

两个容易踩的坑：

- **宿主要能认出这是本地模块**，否则会转去加载远程 `remoteEntry.js`，然后失败：
  - `register.ts` 不能导出空对象 `{}`，注册中心会忽略空资源。至少写 `{ apis: {}, components: {} }`。
  - `package.json` 的 `name` 必须是 `<id>-ui`。
- **真正的子应用链路本地测不到**：远程入口加载、micro-app 沙箱、宿主下发登录态，只有部署到后端（第 ⑤ 步之后）才能验证。本地只保证页面本身没问题。

### 4.4 子应用代码约束

- 登录态、全局数据由宿主下发（`microApp.getGlobalData()`，`src/package.ts` 已封装），**不要在子应用里自己做登录**。
- 只通过 `moduleRegistry` 调用其他模块公开的能力，不 `import` 其他模块的文件（子应用里它们不存在）。
- 不硬编码域名、Token、应用实例 ID、`/api` 前缀。
- 只把要给别人用的东西放进 `register.ts`；它会进入远程入口，越大加载越慢。

> **规划中（未实现）**：独立仓库、独立部署的新微前端契约（`@jetlinks-web/application`、应用根组件 + 公共默认布局），见 [运行时应用根组件与微前端迁移](../src/utils/theme-config/README.md)。现在按上面的方式开发，迁移成本最低。

## 5. 自定义样式与布局

### 5.1 样式规则

**用主题变量，不写死值：**

| 用途 | 变量 |
| --- | --- |
| 间距（4px 步进） | `--space-1` … `--space-*` |
| 字号 | `--fs-h1` `--fs-h2` `--fs-h3` `--fs-h4` `--fs-body` `--fs-sm` `--fs-caption` |
| 主色 | `--primary-color`、`--primary-color-1`（浅底）、`--primary-color-active` |
| 主题公共变量 | `--jet-theme-*` |

```css
/* 兼容写法：JetLinks 变量优先，AntD 变量兜底 */
color: var(--primary-color, var(--ant-color-primary, #1677FF));
```

**作用域：**

- 页面样式一律 `<style scoped>`，类名带模块前缀（`.training-*`）。
- 改 AntD 组件内部用 `:deep()`，并且挂在自己的类名下：`.training-workorders :deep(.ant-table) { … }`。
- **禁止**：`html`、`body`、`:root`、裸 `.ant-*` 全局选择器；`document.documentElement.style.setProperty(...)`；新增 Less `@primary-color`。
- 尺寸用 rem / 变量，不用 px 写死；宿主按 1K / 2K / 4K 自动缩放 `html` 字号。

完整变量与规则：[theme-config/README.md](../src/utils/theme-config/README.md)。

### 5.2 布局三档，能用低档就别用高档

| 档 | 场景 | 做法 |
| --- | --- | --- |
| ① 默认布局 | 普通列表、详情、表单 | 什么都不用做 |
| ② 调内容面板 | 页面要全屏画布 / 自绘背景 / 不要白底阴影 | `getContentPanelOverrides()` |
| ③ 应用外壳 | 应用要自己的侧栏、顶栏、驾驶舱 | `getApplicationShell()` |

**② 内容面板**（只在项目布局生效）：

```ts
// index.ts
export default {
  // ...
  getContentPanelOverrides: () => ({
    'training/Dashboard': false,                 // 不套面板，页面自绘
    'training/Board': { background: false },     // 保留留白，去白底和阴影
    'training/Report': { padding: 0 },           // 改内边距
  }),
}
```

键填菜单 `code` 或路由 path。页面里不要再自己包 `ContentPanel`，否则会出现双层卡片。详见 [页面内容面板与页面头部插槽](./页面内容面板与页面头部插槽.md)。

### 5.3 应用外壳

`index.ts` 加：

```ts
import type { ApplicationShellContext } from '@jetlinks-web-core/types/module'

// export default 对象内：
getApplicationShell: () => ({
  component: () => import('./shells/TrainingShell.vue'),
  match: ({ hasMenu }: ApplicationShellContext) => hasMenu('training/WorkOrders'),
}),
```

`shells/TrainingShell.vue`：

```vue
<template>
  <!-- 必须单根：宿主会给根节点挂 jl-app-scope 和 data-jl-app -->
  <div class="training-shell">
    <aside class="training-shell__sider"><!-- 自己的侧栏 --></aside>
    <main class="training-shell__content">
      <PageRouteView />          <!-- 必须有路由出口，否则页面全空 -->
    </main>
  </div>
</template>

<script setup lang="ts">
import PageRouteView from '@jetlinks-web-core/components/PageRouteView/index.vue'
</script>

<style lang="less">
/* 外壳的非 scoped 样式必须包在 .jl-app-scope 下 */
.jl-app-scope .training-shell {
  display: flex;
  min-height: 100%;
  &__sider { width: 15rem; }
  &__content { flex: 1; padding: var(--space-3); }
}
</style>
```

要点：

| 规则 | 说明 |
| --- | --- |
| 只在应用运行态生效 | URL 必须带 `?applicationScope=<实例ID>` |
| `match` 用菜单 `code` | 不能用路由路径；不硬编码实例 ID |
| 没命中 | 回落默认布局，控制台打印 `[Application Shell] ... did not match` |
| 多个模块命中 | `priority` 大者胜，优先收窄 `match`，而不是加大 priority |
| 外壳无 props | 菜单、用户从 store 取：`useMenuStore().siderMenus`、`useUserStore()` |
| 菜单只用已授权数据 | 不在外壳里自己拼菜单 |

只想往默认顶栏插按钮、不需要整套外壳时，用 `getRegisterComponents()`，参考消防模块入口 `runtime-ui/modules/fire-control-saas-ui/runtime/index.ts`。

完整教程：[应用自带外壳接入指南](./应用自带外壳接入指南.md)。

## 6. 排障

| 现象 | 先查 |
| --- | --- |
| 模块整个不生效 | `index.ts` 有没有 `export default`；`filter: true`；新建后没 `pnpm install` / 重启 |
| 菜单设置里没有候选 | `baseMenu.ts` 是否导出；`showPage` 权限 ID 在目标环境是否存在 |
| 改了菜单线上没变 | 服务端菜单未同步 → 重走菜单设置 + 重新授权 |
| 有菜单，页面空白 / 404 | `code` ↔ `views/` 大小写；外壳缺路由出口 |
| `xxx is not exported` | `import` 了别的模块文件 → 改走 `moduleRegistry` |
| 接口 401 / 403 | 401：登录态 / 没走宿主 `request`；403：菜单 `permissions` 漏配或未授权 |
| 切应用后显示旧数据 | hook 没按路由重查 / 没丢弃迟到响应 |
| 外壳不生效 | URL 无 `applicationScope`；`match` 的 code 不在菜单里 |
| 样式串到别的页面 | 有全局选择器，或外壳样式没包 `.jl-app-scope` |
| 微前端页面加载不出 | `/system/resources/ui` 有无该 id；`<path>/index.html`、`remoteEntry.js` 能否访问；三个 ID 是否一致 |
| 改完代码没变化 | `pnpm -F jetlinks-web-core dev:force` 清 Vite 缓存 |
