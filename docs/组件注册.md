# Registry 扩展体系 & useRegistryOptions 使用文档

> 目标：
> **在不修改原页面代码的前提下，实现插件化 UI 扩展，并彻底避免 Vue 响应式递归更新问题**

> 示例：参考设备详情页 `modules/device-manager-ui/views/device/Instance/index.vue`
---

## 一、整体架构说明（必读）

### 1.1 分层设计（核心思想）

```
┌──────────────┐
│ Parent Page  │  ← 唯一状态源（options）
└──────┬───────┘
       │
┌──────▼──────────────┐
│ useRegistryOptions  │  ← 纯派生 / 可控同步
└──────┬──────────────┘
       │
┌──────▼──────────────┐
│ componentsRegistry  │  ← 插件注册中心
└──────┬──────────────┘
       │
┌──────▼──────────────┐
│ RegisterComponents  │  ← 纯渲染容器（无状态）
└─────────────────────┘
```

### 1.2 核心原则（非常重要）

> **派生数据永远不能回写自己的依赖源**

因此：

* ❌ RegisterComponents 不处理 options
* ❌ 不在 computed 上 watch 再 emit
* ✅ options 只在父组件中维护
* ✅ registry 只描述「扩展意图」

---

## 二、核心模块说明

### 2.1 componentsRegistry（注册中心）

#### 注册 Key 规则

```ts
${route.name}:${code}
```

示例：

| 页面           | code    | registryKey          |
| ------------ | ------- | -------------------- |
| DeviceDetail | tabs    | DeviceDetail:tabs    |
| DeviceDetail | content | DeviceDetail:content |

---

#### RegistryItem 定义

```ts
interface RegistryItem {
  code: string                 // 插件唯一标识
  target?: string | number     // 目标 key
  mode?: 'replace' | 'before' | 'after'
  component?: Component        // 插入组件
  props?: Record<string, any>  // 组件 props
  extraOptions?: any           // tabs / list 扩展项
}
```

---

## 三、useRegistryOptions（核心 Hook）

### 3.1 作用

* 将 **baseOptions + registryItems** 合并成新 options
* 不直接修改 baseOptions
* 不产生递归更新
* 支持只读 / 自动同步 / 手动同步

---

### 3.2 API 定义

```ts
const {
  mergedOptions,   // 派生后的 options（只读）
  syncOptions      // 同步回 baseOptions（可选）
} = useRegistryOptions({
  baseOptions,
  registryItems,
  autoSync
})
```

---

### 3.3 参数说明

| 参数            | 类型                  | 说明                     |
| ------------- | ------------------- | ---------------------- |
| baseOptions   | Ref<Array>          | 父组件维护的原始 options       |
| registryItems | Ref<RegistryItem[]> | 插件注册项                  |
| autoSync      | boolean             | 是否自动回写 baseOptions（谨慎） |

---

## 四、标准使用方式（推荐）

---

### 4.1 Tabs 扩展（最常见场景）

#### 父组件

```ts
const baseTabs = ref([
  { label: '基本信息', value: 'base' },
  { label: '设备数据', value: 'data' }
])

const registryItems = computed(() =>
  componentsRegistry.getRegistry('DeviceDetail:tabs') ?? []
)

const { mergedOptions: tabs } = useRegistryOptions({
  baseOptions: baseTabs,
  registryItems
})
```

```vue
<a-tabs :items="tabs" />
```

---

#### 插件注册

```ts
componentsRegistry.register('DeviceDetail:tabs', {
  code: 'alarm-tab',
  extraOptions: {
    label: '告警信息',
    value: 'alarm'
  }
})
```

---

### 4.2 replace / before / after 模式

```ts
componentsRegistry.register('DeviceDetail:tabs', {
  code: 'replace-data',
  target: 'data',
  mode: 'replace',
  extraOptions: {
    label: '实时数据',
    value: 'data'
  }
})
```

## 五、RegisterComponents 使用说明

### 5.1 定位

> **RegisterComponents 是“插件插槽容器”，不是状态管理组件**

---

### 5.2 基础用法

```vue
<RegisterComponents code="content">
  <BaseInfo key="base" />
  <DeviceData key="data" />
</RegisterComponents>
```

插件：

```ts
componentsRegistry.register('DeviceDetail:content', {
  code: 'alarm-view',
  target: 'data',
  mode: 'after',
  component: AlarmView
})
```

---

### 5.3 activeKey（内容区切换）

```vue
<RegisterComponents
  code="content"
  :activeKey="activeTab"
>
```

特点：

* 不卸载组件
* 只控制 display
* 状态不丢失

---

### 5.4 wrapper（is）

```vue
<RegisterComponents
  is="a-space"
  code="actions"
>
```

---

## 六、插件 / 子模块注册规范（强烈推荐）

### 6.1 插件入口注册

```ts
export function setupDevicePlugin() {
  componentsRegistry.register('DeviceDetail:content', {
    code: 'plugin-view',
    component: PluginView
  })
}
```

只调用一次即可。

## 七、禁止事项（重要）

❌ 在 RegisterComponents 中处理 options
❌ watch computed 再 emit
❌ registry 中操作业务状态
❌ 依赖 slot 顺序写业务逻辑

---

## 八、为什么这套方案不会再出现递归更新？

### 唯一原因：

> **派生值从不回写自己的依赖源**

| 项目            | 是否回写    |
|---------------| ------- |
| mergedOptions | ❌       |
| code          | ❌       |
| baseOptions   | ✅（仅父组件） |

---

## 九、常见问题（FAQ）

### Q：registry 会影响性能吗？

A：

* registryItems 通常很小
* 无 deep watch
* computed 派生
* 可支撑插件级规模

---

### Q：插件能卸载吗？

A：

```ts
componentsRegistry.remove(code)
```

---

### Q：支持 SSR / keep-alive 吗？

A：

* 是纯计算 + 渲染逻辑
* 无副作用
* 天然支持

### Q: 为啥我加了组件但是目标组件还是没有变化？
A:

* RegistryComponent 包裹的组件都需要key值，且key值需要和注册组件的target值一致

    <a-button>

    </a-button>

      <a-menu>

          <j-permission-button

### 单个动态组件场景
activeKey 控制单个显示
```vue
// 父组件
<j-page-container
  :tabList="mergedOptions"
  :showBack="true"
  :tabActiveKey="instanceStore.tabActiveKey"
  @tabChange="onTabChange"
>
  <RegistryComponent code="detail-tabs" :activeKey="instanceStore.tabActiveKey">
    <component
      ref="componentRef"
      :key="instanceStore.tabActiveKey"
      :is="tabs[instanceStore.tabActiveKey]"
      v-bind="{ type: 'device',isRefresh: isRefresh }"
      @onJump="onTabChange"
    />
  </RegistryComponent>
</j-page-container>

<script lang="ts" setup>
  import { useRegistryOptions } from '@jetlinks-web-core/hooks'
  
  const list = ref([])
  const { mergedOptions } = useRegistryOptions({ baseOptions: list, code: 'detail-tabs' })
</script>
```
