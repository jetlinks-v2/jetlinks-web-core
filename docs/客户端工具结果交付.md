## 1. 责任边界

客户端业务工具声明 typed producer/consumer port 与 typed result；共享 compiler 投影 routing/catalog，共享 Result Adapter 生成本次执行的
binding、范围、数量、完整性和 evidence。业务工具不上传会话文件、不拼物理路径、不组装 binding/evidence envelope，也不声明 renderer capability。

当前实现状态：

- canonical producer/consumer 由 typed definition 同源编译 `name/type/mediaType/shape`，consumer 额外保留
  `required/sourcePolicy`；新增或修改的业务工具只允许这条写入路径；
- `portVersion=ai-tool-port/v1`、`consumerPorts`、`producerPorts` 是 canonical wire；`accepts/produces/outputShapes/prerequisites` 仅由 compiler 单向生成兼容投影；
- contract 版本为 `ai-client-tool-contract/v2`，catalog 审计拒绝 canonical port 与兼容投影漂移；
- clientToolAggregatePresentation.ts 已删除，浏览器不生成、修补或改写 ECharts option；
- 后端 canonical presentation compiler 是制图决策和 option 生成的唯一真值源；
- jetlinks-ai-agent-ui 只校验和渲染 canonical source；
- PDF/Word/PPT 与浏览器预览消费同一 presentation source。

发布迁移期仅由 `clientToolDefinition.ts` 集中兼容存量 `name/optional/source` consumer：其中
`name` 只投影为 `accepts/prerequisites`，不猜测 `type/mediaType/shape`，不获得 typed resource authority。
producer 与 consumer 允许单侧先迁移；同一 consumer 声明或数组中混用 canonical/legacy 字段时 fail closed。
业务模块不得复制该 Adapter，存量调用方仍应分批迁移到完整 descriptor。

静态与动态边界：

~~~text
ProducerPort = name + type + mediaType + shape
ConsumerPort = name + type + mediaType + shape + required + sourcePolicy
RuntimeBinding/Evidence = port identity + execution path/ref, range, count, completeness and claims
~~~

Renderer capability 属于会话而非业务工具：

- mediaType/preferredInputShapes：consumer 兼容声明；
- supportsSessionFile/maxInlineBytes/defaultMode：传输能力；
- deliveryPolicy/narrativePolicy：交付体验策略。

## 2. 交付策略

当前 materializer 对单个未区分 audience 的大结果使用以下安全降级链：

~~~text
session-file → explicit safe inline → bounded preview
~~~

1. 会话文件可用且完整 source 未超过文件上限时，写入 session file 并返回 canonical binding。
2. 文件关闭、不可用、上传失败或内容超限时，只有 producer 显式声明的 modelSafeInline 且未超过 maxInlineBytes，才完整 inline。
3. 未声明安全 inline 或超限时，只使用 producer 提供的 bounded preview；preview 不升级为完整 downstream source。
4. 没有安全 preview 时只返回有界 summary 与 warning。
5. 上传取消直接返回 CLIENT_TOOL_ABORTED，不触发 inline 降级。
6. 上传失败先补偿未完成文件，再进入允许的降级路径；历史成功产物不删除。

交付层只处理序列化、容量、唯一命名、上传、取消、清理和 canonical result 装配，不读取业务字段猜语义，也不按 renderer、工具或页面选择策略。

该顺序只适用于未声明 audience 的发布兼容路径。canonical output 已将 grounding、展示和复用拆为三个
audience；materializer 只读取声明的 audience 与 capability，不根据 payload、工具名或 carrier 猜测。

### 2.1 Audience-aware delivery

| audience | canonical 内容 | 默认消费者 | 交付约束 |
| --- | --- | --- | --- |
| `model-evidence` | claims、criteria、cardinality、coverage、limitations 与有界安全样本 | 模型上下文 | 只允许 bounded model-safe inline；完整 rich records 默认不可见 |
| `client-presentation` | renderer-ready 表格、图、卡片或媒体 source | 当前会话 renderer | 可 client-only inline 或 session-file；默认不进入模型 |
| `reusable-source` | 完整、可复用、可校验的 canonical source | downstream consumer | 必须保持 exact identity/digest；bounded preview 不满足 |

audience 是 output projection 的可见性/交付属性，不是新的资源 owner。一个 source 可以产生多个 projection，但必须共享
同一 binding/source evidence identity；不得复制数据后生成互不关联的 Evidence。audience 不授予权限、absence authority、
完整性、Task 完成权或 presentation obligation，也不改变静态 `type/mediaType/shape`。
后端 terminal audit 直接消费 canonical Evidence/obligation，不把 `model-evidence` 当成新的审计真值源。

`auto` 按 audience 确定性决策，不使用全局 inline-first 或 file-first：

1. `model-evidence`：只 inline producer/server 已归一化且明确 model-safe 的有界投影；超预算时保留 claims、
   cardinality、limitations 与稳定 selector，不把完整结果塞入模型上下文。
2. `client-presentation`：renderer 兼容、内容通过安全校验且未超过当前 renderer/client 额度时可 client-only inline；
   需要复用、超限或 capability 指定 file 时使用 exact session-file/ref。两者都不可用时，optional 才能降级为
   bounded preview，required 必须保持 partial/open。
3. `reusable-source`：默认使用 exact session-file/ref；仅当 source 显式安全、有界且 consumer 接受 inline exact
   source 时允许 inline。preview、viewport 与 model sample 永远不能满足该 audience。

每次决策至少绑定 audience、requiredness、canonical port identity、实际字节数、安全结论、renderer capability、
delivery mode、binding/source identity 与 completeness。取消、上传失败、超限、文件不可用、malformed/ambiguous、
media/shape mismatch 或缺少 exact ref 继续 fail closed，不能拿另一 audience 的 projection 偷换 required source。

Web Core materializer 是 projection carrier 与 exact source identity 的唯一 owner。业务工具只声明 output audience 和
source；materializer 对 JSON canonical source 或实际写入的 NDJSON bytes 计算稳定 `sha256:<hex>`，并把同一个
`sourceDigest` 写入 exact inline/session-file binding。物理 ref、路径和 carrier 不参与 digest；partial、truncated、
bounded preview/model sample 不携带 exact digest，也不能满足 `client-presentation` 的 required obligation 或
`reusable-source`。Web Crypto 不可用时 canonical exact projection fail closed，released legacy 路径保持原有容错。

## 3. Artifact 与 Record Stream

AiClientToolRecordStream 处理记录流；AiClientToolArtifact 描述 producer 已准备好的 renderer-neutral source：

| 字段 | 语义 |
| --- | --- |
| content | 完整内容；只供 session-file materialization，不自动进入模型 |
| mediaType/fileExtension | 编码与安全扩展名 |
| outputShape/bindingName | producer-owned output identity |
| recordCount | 完整 artifact 实际记录数 |
| totalCount | 当前查询范围内已知总数；未知不猜 |
| displayedCount | 仅 source 本身为 partial 时出现 |
| modelPreviewCount | 内部模型样本数，不进入用户事实 |
| maxBytes | session-file 内容上限 |
| modelSafeInline/maxInlineBytes | producer 审核的安全 inline 及上限 |
| preview | producer 显式生成的有界预览 |

完整 source 12 条、模型样本 5 条时，用户事实仍是 recordCount=12、returnedCount=12、complete=true；
modelPreviewCount=5 只属于内部投影。只有实际 source 降级为 5/12 时才声明 displayedCount=5、complete=false、truncated=true。
viewport、分页和虚拟滚动数量不回写 source 完整性。

结果信息分为：

- userClaims：可进入用户回答和事实审计的权威事实；
- cardinality/coverage：record、bucket、measurement、sample 和覆盖范围等完整性元数据；除非业务 owner 明确声明其本身就是用户目标，否则不生成 headline claim；
- resources：runtime 可物化的 opaque descriptor；
- modelSample：有界结构样本，不升级为用户事实或 downstream source；
- runtimeDiagnostics：阈值、截断原因和传输状态。

### 3.1 静态端口与运行时物化载体

静态 output kind 描述 producer 交付给 downstream consumer 的逻辑资源，不由运行时载体反推：

- `artifact` 是文件型业务产物，compiler 固定生成 `type=artifact`、`delivery=file`，不能满足要求结构化 inline/typed source 的 renderer；
- renderer-ready 结构化结果集声明为 `recordSet`，compiler 生成 `type=structured-data`、`delivery=auto`，并保留 producer 声明的 `mediaType`、`shape`、`recordPath` 与 cardinality；
- `AiClientToolArtifact` 只是 renderer-neutral 的运行时 materialization carrier。结构化 producer 可以使用该 carrier 在 inline、session-file 与 bounded-preview 之间安全交付，但 canonical binding 仍来自静态 structured output，不能被重类型为文件型 artifact port。

required presentation 与 producer 的兼容性只允许基于 canonical `type/mediaType/shape/delivery` 判断。media type、shape、资源类型或交付能力任一不兼容，或候选 malformed/ambiguous 时必须 fail closed；诊断只报告 canonical 声明是否兼容，不参与工具选择、执行或终态裁决，也不创建第二套 routing/catalog/ledger。一个不兼容 producer 不得使无关 sibling 失效。

### 3.2 Required typed presentation 契约

- owner 与范围：`ui/jetlinks-web-core` 继续唯一拥有 typed output compiler、canonical binding 与 renderer-neutral
  兼容性诊断；业务 handler、接口、renderer、会话协议和后端 admission 不获得同类 owner。
- 当前合同：静态 `artifact` 固定编译为 `artifact/file`，renderer-ready 结构化结果使用
  `recordSet -> structured-data/auto`；required presentation 诊断只读取 canonical
  `type/mediaType/shape/delivery`，对 malformed、ambiguous 和不兼容候选 fail closed，并隔离 sibling。
  运行时 materialization carrier 不改变静态 output kind。
- 长期门禁：compatible、artifact/file、media/shape mismatch、malformed/ambiguous、sibling isolation、
  inline/session-file identity 等价及 bounded-preview fail-closed 必须由匿名合同覆盖；具体测试数量和构建日志留在 PR/CI。

### 3.3 Compatibility preflight 与 runtime admission

- catalog/registration 目标接入只使用 canonical `type/mediaType/shape/delivery/audience` 检查 descriptor 自洽和
  producer/consumer 静态兼容性，输出 typed diagnostic；它不执行工具、不选择本轮 producer、不关闭 Task，也不创建第二套 catalog。
- runtime producer/target port admission 仍由后端当前 Task、ToolSurface、Evidence 与 Delivery requirement 决定；
  前端 diagnostic 只能帮助发布前发现静态端口错误，不能成为 terminal verdict。
- materialization 在 handler 成功后根据实际大小、session-file 和 renderer capability 决定 delivery。运行时
  `AiClientToolArtifact` 等 carrier 不得反推静态 output kind，也不得将 file artifact 重类型为 structured source。
- `AiClientToolArtifact` 与 `AiClientToolRecordStream` 复用同一个 audience-aware decision。record stream 在 renderer
  inline 额度内保留 exact client-only source，实际大小越界时才切换 exact session-file；`model-evidence` 不写文件，
  `reusable-source` 无 exact inline/ref 时保持 partial。NDJSON file 与 inline records 使用同一 actual-source digest，
  sample/preview 永远不升级为 exact binding。
- empty 只改变 Evidence/absence 语义，不授予 Delivery completion。canonical 空结果仍走同一 carrier admission：
  `model-evidence` 可 bounded inline empty；required `client-presentation` 必须获得 compatible inline 或真实 exact file/ref；
  `reusable-source` 默认仍需 exact ref，除非 consumer 明确接受 exact inline。空内容 digest、`totalCount=0` 或 sample path
  都不能替代 required carrier proof。
- 不兼容或 malformed candidate 只隔离自身；合法 sibling、已提交 Evidence 和无关 renderer 不受牵连。

## 4. Binding 标签、范围与 ordering

- 静态 name/shape/mediaType 保持 port identity，不因展示 label 改变。
- resolveLabel 只能消费 producer 已声明的 label、semanticRole、measure、aggregation 和 ordering。
- requestedRange/observedRange 随同一 binding 经过 inline、record stream、session-file 和 fallback，交付方式不改变覆盖判断。
- materialized output 未声明更具体范围时，继承本次 producer evidence 范围。
- ordering 只接受显式字段、方向和 producerGuaranteed；不从样本、字段名、工具 ID、页面或用户原文推断。
- 无效 ordering 整体 fail closed，但不损坏原始结构化 binding。

## 5. 文件生命周期与补偿

默认文件名由稳定工具段、可读时间和 execution UUID 组成。call.id 只用于调用关联，不能承担跨 turn 唯一性；同一执行分块复用路径，不同执行永不覆盖。

内部状态为：

~~~text
not-started → unknown → opened → committed
                         ↘ rolled-back
~~~

- 请求发出但未确认时为 unknown，分片成功后为 opened，结果完成装配后才 committed。
- 只有 unknown/opened 允许幂等补偿删除。
- 用户主动删除保持严格 404；交付补偿使用 ignoreMissing=true。
- ignoreMissing 只容忍目标已不存在，权限、非法路径和存储错误仍传播。
- 未声明 audience 的发布兼容记录流在 count=0 时保持 inline empty 且不上传文件；canonical audience 若要求 exact
  session-file/ref，则上传真实零字节 NDJSON 并计算同源 digest，缺少 required carrier 时保持 partial/open。

已持久化 fs:// 引用只读恢复，不迁移、不双写。业务工具显式 writeToPath 时，覆盖/追加语义仍由该工具拥有，不被默认 materializer 接管。

## 6. 输入默认值与叙事策略

AiClientToolInput.defaultValue 是 provider-neutral 业务契约。clientToolRouting.ts 将其投影为 PropertyMetadata.expands.default，provider adapter 再处理模型方言；执行层仍使用同一业务常量做最终默认和值域校验。

Renderer 的 narrativePolicy 只指导正文组织，不改变权限、工具可达性、presentation obligation 或终态：

| mode | 默认职责 |
| --- | --- |
| card-first | 卡片承载明细时只保留摘要和可选下一步 |
| analysis | 允许基于 evidence 解释趋势、比较和异常 |
| free | 无卡片职责时保持普通正文 |

策略使用低基数 token 和有界上限；runtime 不因 narrativePolicy 改写模型正文。

## 7. 客户端动作确认与工具事实闭环（已实施）

### 7.1 目标与边界

目标是让客户端工具的声明、执行、确认和结果展示形成同一个可审计闭环：业务模块只声明稳定输入、typed
producer/consumer port、副作用和业务执行；共享 runtime 负责 catalog 快照、参数绑定、确认、执行状态和结果交付；会话 UI
只展示 runtime 已确认的状态，不把“用户已同意”误当成“工具已执行成功”。

影响范围与 owning module：

- `ui/jetlinks-web-core/src/layout/components/AiChat/`：客户端工具 authoring facade、catalog/snapshot、确认与执行编排、
  structured navigation/result adapter；
- `ui/modules/jetlinks-ai-agent-ui/components/AgentConversation/`：按 tool call id 关联确认和执行结果，展示完整状态；
- 首个业务 adopter 为 `ui/modules/device-manager-ui/agentCapabilities/deviceAnalysis/`，业务约束记录在该模块
  `Business.md`。

本计划不修改后端 FLAT `requestTools` 投影、不让前端按模型轮次筛选工具、不改变 canonical presentation renderer、
不改变设备查询接口和权限边界，也不复制实现到 `runtime-ui/`。FLAT 普通业务轮保持完整声明集属于后端独立修复；前端只保证
授权 catalog 的语义快照稳定、声明可编译、执行结果可追踪。

### 7.2 实施步骤

1. **收紧 authoring contract**：catalog 审计增加输入必需性与 consumer port 一致性检查。执行必须依赖某个逻辑资源时，
   consumer 使用 `required=true`；`sourcePolicy=EITHER` 继续允许该资源来自用户明确参数或前序 typed output，不把“可直接传参”
   错误解释成“逻辑依赖可选”。校验失败只拒绝当前 malformed tool，不隐藏有效 sibling。
2. **保持 READ 纯度**：READ 工具不得写 handoff、跳转路由或修改页面状态。查询结果只返回 typed data、cardinality、subject 和
   structured navigation receipt；安全链接和 Markdown 表现由共享适配层根据已授权菜单生成，业务结果不再携带 retry prompt、
   reply policy 或 instructive prose。
3. **建立通用 prepare-confirm-execute 边界**：为 WRITE/EXTERNAL_ACTION 提供可选的 typed prepare 阶段，在确认前解析并校验
   subject、生成有界确认摘要和 prepared arguments；用户确认后使用同一 prepared receipt 执行，并在必要时做最终重校验。
   prepare 失败直接返回结构化 request/permission failure，不弹出针对不存在目标的确认框。该能力是公共扩展点，不按工具 ID
   或设备场景分支。
4. **统一确认与执行状态机**：共享 runtime 按 call id 发布
   `pending-confirmation -> approved/executing -> completed|failed`，拒绝走 `rejected`；`approved` 只是中间态。
   AgentConversation 合并确认事件和 tool result，失败时展示用户可理解的对象与下一步，刷新/重连后仍按权威结果恢复，不把
   “已同意”渲染为终态。
5. **稳定 catalog 生命周期**：保留 registry revision、wire signature、执行快照和 active-execution 延迟发布；补充诊断记录
   catalog revision/signature、工具总数、malformed 数量和本次 call 所属 snapshot。业务 provider 不读取 WebSocket/session 字段，
   不自行创建 FLAT/HYBRID declaration epoch。
6. **收敛 failure/recovery**：参数无效、目标不存在、权限不足、依赖不可用和用户拒绝使用既有 typed failure disposition 与
   recovery action；修复建议通过字段、逻辑资源或 capability 表达，不在业务结果中写模型提示词。正文只能依据成功 tool result
   声称操作完成。

### 7.3 风险与兼容

- prepare 是公共 authoring contract 的可选新增阶段；存量工具保持原执行路径，不添加旧字段别名或双协议。首个 adopter 验证后
  再按工具族迁移，未迁移工具不自动获得“已预校验”语义。
- structured navigation 必须经过当前菜单授权解析；无法绑定已授权菜单时只返回业务 subject，不生成或猜测 URL。
- 确认状态需要与后端/客户端 tool result 的 call id 稳定关联；缺少最终结果时显示“状态未知/可重试”，不得推断成功。
- catalog 诊断只记录低基数 revision、signature、计数和工具 ID，不记录 token、完整参数、敏感结果或用户原文。

### 7.4 验证目标

- contract 单测覆盖 required consumer + `EITHER`、malformed sibling 隔离、READ 隐藏副作用拒绝或审计、prepare failure、
  用户拒绝、执行成功、执行失败和重校验失败；
- snapshot 测试覆盖同 schema handler 刷新、执行中 revision 延迟发布、刷新/重连后 call 使用原快照；
- AgentConversation 测试覆盖“已确认后成功”“已确认后失败”“拒绝”“刷新恢复”，确保 `approved` 不作为终态；
- owning module 定向测试覆盖模糊名称、显式 ID、typed lookup ID、无效 ID、无权限目标和单一/多候选；
- 阶段性统一运行 `jetlinks-web-core` contract/type tests、`jetlinks-ai-agent-ui` 定向测试、owning module 工具测试与窄构建，
  最后使用应用内浏览器验证完整确认和导航闭环；不在每个小步骤重复全量构建。

### 7.5 实施结果

- `clientToolDefinition.ts` 与 `clientTools.ts` 已增加只适用于 `WRITE/EXTERNAL_ACTION` 的可选
  `prepare` 扩展点；预校验参数在确认期间锁定，确认摘要有长度上限，存量未迁移工具保持原路径。
- `AgentConversation/clientToolConfirmationState.ts` 按 call/interaction 关联权威 tool result，将确认后状态区分为
  `approved/executing`、`completed`、`failed` 和 `rejected`；实时与历史恢复共用同一结算逻辑。
- 集中验证通过：`jetlinks-web-core` contract 60/60（行覆盖率 96.24%）、definition 类型检查、
  prepare 生命周期 3/3；`jetlinks-ai-agent-ui` 确认结算 4/4；`device-manager-ui` 工具契约 20/20；
  `device-manager-ui` 与 `jetlinks-ai-agent-ui` 窄构建通过。

## 8. bounded analytical authoring 契约

### 8.1 当前结论与目标

Web Core 提供稳定、wire-free 的 analytical producer DSL。业务工具只声明自己的语义标识、事实族、subject、measure、dimension、
filter、criterion、coverage，以及 bounded criterion 对应的 semantic measure、physical value field、coordinate field、静态 axis 或
`axisFromInput`、`boundedBy` input 和 output binding；唯一 compiler 将这些通用事实映射为
`expands["x-ai-routing"].analyticalCapability` 和执行期 canonical output binding。`version`、`capabilityId`、`semanticKey`、
`transformCost`、wire completeness、`producerGuaranteed` 和 proof 生成均留在 Web Core adapter 内部，业务执行器只返回业务数据与
普通 success/partial 状态。

bounded completeness 相对本次 canonical requested scope 判断，而不是要求 producer 证明候选全集：只有普通 success、正的安全整数 limit、
limit 位于声明值域、显式选中的 output 为数组且返回数量不超过 limit 时，才保持 complete；真实 pagination/continuation、业务 partial、
缺失或非法 limit、output 未选中或绑定不唯一、返回数量越界均降级为 `analytical_scope_unproven`，不生成 authoritative complete evidence。

### 8.2 owner、范围与非目标

- 唯一 owner：`ui/jetlinks-web-core/src/layout/components/AiChat/clientToolDefinition.ts` 及其 public `clientToolApi.ts`；
  `clientToolRouting.ts` 只保留内部 wire DTO 与 canonical normalizer。
- adopter：`ui/modules/jetlinks-ai-ui/agentCapabilities/passengerFlow/tools.ts` 与
  `ui/modules/jetlinks-ai-ui/agentCapabilities/aiSearch/tools.ts` 只做机械迁移，不复制 DTO、compiler、proof 或 routing helper。
- 受保护范围：设备、客流、问图首页推荐 provider、locale、测试与 owning 文档原样保留；推荐文案不得被 routing、selection、
  completeness、Evidence 或 terminal policy 读取。
- 不修改业务 HTTP/transport/query/service、排序、limit 值域、菜单、页面壳、renderer、后端 wire、Task/Evidence/epoch/Delivery，
  不新增按业务名、工具名、关键词、字段 shape、fixture、prompt 或模型的分支。

### 8.3 当前 contract 与实现

1. Web Core 提供 generic analytical producer 与 bounded analytical producer 两种 typed helper。业务侧的 `producerKey` / `factKey`
   是稳定业务语义标识，compiler 分别映射到 wire identity；`coverage` 映射 wire completeness，`version` 与 `transformCost` 使用
   adapter-owned canonical 值。普通 producer 可直接声明 semantic ordering；bounded producer 只在 criterion binding 中声明一次
   measure、direction 与 physical value field，compiler 同时生成 semantic capability ordering 和 physical output ordering。
2. `boundedBy` 必须显式指向 `TArgs` 中的一个 input，output binding 必须显式指向同一工具的一个 output name。compiler 只按这两个
   显式标识解析物理端口；output shape 从已绑定 output 读取，bounded input 自动进入 wire filters。禁止根据 filters、字段顺序、label、
   output shape 或数组位置猜配。
3. canonical output field 使用 `measure` 表达 measure identity，使用 `axis` 表达 dimension identity；二者都不得回退到物理字段名。
   bounded criterion 必须显式绑定一个已声明 measure、该 measure 的 physical value field、一个 physical coordinate field，以及唯一的
   static axis 或 `axisFromInput`。compiler 只接受精确一一映射；动态 axis 只能取自本次调用中显式绑定的 input，且必须属于 producer
   已声明 dimensions，禁止从字段 shape、label、数组位置或样本值猜测。
4. bounded helper 返回 opaque authoring handle，不暴露 capability DTO 或 proof API。执行器只返回业务数据和普通 success/partial；
   Web Core 在同一次 compiled tool 调用内自动绑定 declared scope、canonical limit、selected output、criterion 和 runtime axis。只有
   success、有效正整数 limit、已选中目标数组且数量不超过 limit，并且 measure/value/coordinate/axis 映射全部有效时，才保持
   requested-scope complete；其他情况统一 fail closed。
5. 删除当前未发布的 raw `AiClientToolAnalyticalCapability` public export、`defineClientToolAnalyticalCapability`、
   `defineClientToolBoundedScope`、`ClientToolAnalyticalCompletionProof` 与 `analyticalCompletion` result option，同步迁移全部 AI UI
   analytical adopter，不保留同 PR 过渡别名。已发布 legacy name/effect/typed/routed/plain/remote-adapted 工具格式继续走现有兼容 owner。
6. 真实 pagination/continuation、业务 partial、64 KiB 且无 exact ref、malformed/ambiguous/unselected、显式 binding 不匹配和
   canonical/legacy conflict 继续局部 fail closed；一个 malformed sibling 不得使合法 producer、catalog 或 session 失效。

### 8.4 验证矩阵与剩余风险

- Web Core 匿名合同覆盖 canonical `axis` 归一化、非法 axis fail closed、static axis、两种 runtime axis 共用同一 physical coordinate
  field、criterion measure 与 physical value field 精确映射、semantic/physical ordering 一致，以及 missing/ambiguous/unselected/
  mismatched mapping 不产生 authoritative completeness。
- bounded Top-N 继续覆盖 `< limit`、`== limit`、候选总体 `> limit` 但请求仅为 Top-N 和 criterion sibling；pagination、64 KiB
  oversize、exact ref、malformed sibling、canonical/legacy conflict 与 legacy name/effect/typed/routed/plain/remote-adapted 回归不放宽。

  首页推荐 provider、locale、测试和 owning 文档完整保留，也不得被 routing/completeness 读取。

### 8.5 工具结果生命周期与展示状态

`session.tool_result` 是工具调用的终态事件；结果中的 `complete/truncated/completeness` 只描述本次结果交付完整性，
`supportsAbsenceClaim` 单独描述空结果结论权限，三者不得互相反推。Web Core 的 `clientToolResult.ts` 是通用结果状态解析的唯一
owner，按 canonical `evidence`、顶层 canonical mirror、已发布 legacy `success/ok/status/outcome` 的顺序生成只读投影：
`executionStatus`、`resultCompleteness`、`evidenceCoverage`、`absenceAuthority` 和 conflict diagnostic。canonical 与 mirror 冲突、
malformed completeness 或 partial source 声称 absence authority 时必须 fail closed，不能提升为 complete/supported；缺少 completeness 的
legacy success 仍可完成调用，但展示为 unknown，不能猜成完整。

Agent Conversation 只消费该共享投影：收到 `session.tool_result` 后按 `executionStatus` 将对应 tool call 收敛为 completed/failed，
不再把 partial 当作运行中状态；结果卡把 complete 显示为“调用完成”，把 partial/truncated 显示为中性告警“调用完成 · 范围有限”，
unknown 只显示调用已结束，失败才使用红色。前端不得据此改写 assistant transcript、生成终态 fallback、解析业务字段或推断不存在结论。
现有业务 producer、HTTP/query、`x-ai-routing`、64 KiB guard、canonical presentation 和后端 Terminal Decision 均不在本切片修改范围。

## 9. 非目标与门禁

禁止：

- 根据工具名、页面、设备、属性名、字段名、模型/provider 或用户句式特调；
- 在浏览器从 records/aggregate 派生 ECharts option；
- 自动把 content 视为安全 inline；
- 缺少 audience 时根据工具名、payload shape、recordPath 或运行时 carrier 猜 projection；
- 用 `client-presentation` 或 `reusable-source` 的完整内容补偿 `model-evidence` grounding 缺口；
- 让模型构造文件路径、签名 URL、完整 source 或物理 binding；
- 把 preview、model sample 或 viewport 数量冒充完整结果；
- 复制实现到 runtime-ui。

验证门禁：

- clientToolContract.test.ts 与 clientToolDefinition.type-test.ts；
- 大结果、空结果、安全 inline、超限 preview、取消、上传失败和幂等补偿测试；
- binding identity、range、ordering、数量与 partial 语义回归；
- renderer 测试证明前端只消费 canonical source；
- iot-ui 等 owning module 的窄构建；
- git diff --check 与旧 presentation adapter/场景特调扫描。
