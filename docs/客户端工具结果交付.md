# 客户端工具结果交付

> 状态：当前交付契约
> owning module：ui/jetlinks-web-core
> 主要入口：src/layout/components/AiChat/clientToolResultDelivery.ts
> 权威端口规范：modules/jetlinks-ai-agent/docs/help/general-agent-tool-definition-spec.md

## 1. 责任边界

客户端业务工具声明 typed producer/consumer port 与 typed result；共享 compiler 投影 routing/catalog，共享 Result Adapter 生成本次执行的
binding、范围、数量、完整性和 evidence。业务工具不上传会话文件、不拼物理路径、不组装 binding/evidence envelope，也不声明 renderer capability。

当前实现状态：

- canonical producer/consumer 由 typed definition 同源编译 `name/type/mediaType/shape`，consumer 额外保留
  `required/sourcePolicy`；新增或修改的业务工具只允许这条写入路径；
- `portVersion=ai-tool-port/v1`、`consumerPorts`、`producerPorts` 是 canonical wire；`accepts/produces/outputShapes/prerequisites` 仅由 compiler 单向生成兼容投影；
- contract 版本为 `ai-client-tool-contract/v2`，catalog 审计拒绝 canonical port 与兼容投影漂移；
- clientToolAggregatePresentation.ts 已删除，浏览器不生成、修补或改写 ECharts option；
- 后端 canonical presentation compiler 是制图决策和 option 生成的唯一真值源；
- jetlinks-ai-agent-ui 只校验和渲染 canonical source；
- PDF/Word/PPT 与浏览器预览消费同一 presentation source。

发布迁移期仅由 `clientToolDefinition.ts` 集中兼容存量 `name/optional/source` consumer：其中
`name` 只投影为 `accepts/prerequisites`，不猜测 `type/mediaType/shape`，不获得 typed resource authority。
producer 与 consumer 允许单侧先迁移；同一 consumer 声明或数组中混用 canonical/legacy 字段时 fail closed。
业务模块不得复制该 Adapter，存量调用方仍应分批迁移到完整 descriptor。

静态与动态边界：

~~~text
ProducerPort = name + type + mediaType + shape
ConsumerPort = name + type + mediaType + shape + required + sourcePolicy
RuntimeBinding/Evidence = port identity + execution path/ref, range, count, completeness and claims
~~~

Renderer capability 属于会话而非业务工具：

- mediaType/preferredInputShapes：consumer 兼容声明；
- supportsSessionFile/maxInlineBytes/defaultMode：传输能力；
- deliveryPolicy/narrativePolicy：交付体验策略。

## 2. 交付策略

大结果和 renderer-ready source 统一采用：

~~~text
session-file → explicit safe inline → bounded preview
~~~

1. 会话文件可用且完整 source 未超过文件上限时，写入 session file 并返回 canonical binding。
2. 文件关闭、不可用、上传失败或内容超限时，只有 producer 显式声明的 modelSafeInline 且未超过 maxInlineBytes，才完整 inline。
3. 未声明安全 inline 或超限时，只使用 producer 提供的 bounded preview；preview 不升级为完整 downstream source。
4. 没有安全 preview 时只返回有界 summary 与 warning。
5. 上传取消直接返回 CLIENT_TOOL_ABORTED，不触发 inline 降级。
6. 上传失败先补偿未完成文件，再进入允许的降级路径；历史成功产物不删除。

交付层只处理序列化、容量、唯一命名、上传、取消、清理和 canonical result 装配，不读取业务字段猜语义，也不按 renderer、工具或页面选择策略。

## 3. Artifact 与 Record Stream

AiClientToolRecordStream 处理记录流；AiClientToolArtifact 描述 producer 已准备好的 renderer-neutral source：

| 字段 | 语义 |
| --- | --- |
| content | 完整内容；只供 session-file materialization，不自动进入模型 |
| mediaType/fileExtension | 编码与安全扩展名 |
| outputShape/bindingName | producer-owned output identity |
| recordCount | 完整 artifact 实际记录数 |
| totalCount | 当前查询范围内已知总数；未知不猜 |
| displayedCount | 仅 source 本身为 partial 时出现 |
| modelPreviewCount | 内部模型样本数，不进入用户事实 |
| maxBytes | session-file 内容上限 |
| modelSafeInline/maxInlineBytes | producer 审核的安全 inline 及上限 |
| preview | producer 显式生成的有界预览 |

完整 source 12 条、模型样本 5 条时，用户事实仍是 recordCount=12、returnedCount=12、complete=true；
modelPreviewCount=5 只属于内部投影。只有实际 source 降级为 5/12 时才声明 displayedCount=5、complete=false、truncated=true。
viewport、分页和虚拟滚动数量不回写 source 完整性。

结果信息分为：

- userClaims：可进入用户回答和事实审计的权威事实；
- cardinality/coverage：record、bucket、measurement、sample 和覆盖范围等完整性元数据；除非业务 owner 明确声明其本身就是用户目标，否则不生成 headline claim；
- resources：runtime 可物化的 opaque descriptor；
- modelSample：有界结构样本，不升级为用户事实或 downstream source；
- runtimeDiagnostics：阈值、截断原因和传输状态。

## 4. Binding 标签、范围与 ordering

- 静态 name/shape/mediaType 保持 port identity，不因展示 label 改变。
- resolveLabel 只能消费 producer 已声明的 label、semanticRole、measure、aggregation 和 ordering。
- requestedRange/observedRange 随同一 binding 经过 inline、record stream、session-file 和 fallback，交付方式不改变覆盖判断。
- materialized output 未声明更具体范围时，继承本次 producer evidence 范围。
- ordering 只接受显式字段、方向和 producerGuaranteed；不从样本、字段名、工具 ID、页面或用户原文推断。
- 无效 ordering 整体 fail closed，但不损坏原始结构化 binding。

## 5. 文件生命周期与补偿

默认文件名由稳定工具段、可读时间和 execution UUID 组成。call.id 只用于调用关联，不能承担跨 turn 唯一性；同一执行分块复用路径，不同执行永不覆盖。

内部状态为：

~~~text
not-started → unknown → opened → committed
                         ↘ rolled-back
~~~

- 请求发出但未确认时为 unknown，分片成功后为 opened，结果完成装配后才 committed。
- 只有 unknown/opened 允许幂等补偿删除。
- 用户主动删除保持严格 404；交付补偿使用 ignoreMissing=true。
- ignoreMissing 只容忍目标已不存在，权限、非法路径和存储错误仍传播。
- 记录流成功且 count=0 时直接返回完整 empty evidence，不上传空 NDJSON，也不发起删除。

已持久化 fs:// 引用只读恢复，不迁移、不双写。业务工具显式 writeToPath 时，覆盖/追加语义仍由该工具拥有，不被默认 materializer 接管。

## 6. 输入默认值与叙事策略

AiClientToolInput.defaultValue 是 provider-neutral 业务契约。clientToolRouting.ts 将其投影为 PropertyMetadata.expands.default，provider adapter 再处理模型方言；执行层仍使用同一业务常量做最终默认和值域校验。

Renderer 的 narrativePolicy 只指导正文组织，不改变权限、工具可达性、presentation obligation 或终态：

| mode | 默认职责 |
| --- | --- |
| card-first | 卡片承载明细时只保留摘要和可选下一步 |
| analysis | 允许基于 evidence 解释趋势、比较和异常 |
| free | 无卡片职责时保持普通正文 |

策略使用低基数 token 和有界上限；runtime 不因 narrativePolicy 改写模型正文。

## 7. 非目标与门禁

禁止：

- 根据工具名、页面、设备、属性名、字段名、模型/provider 或用户句式特调；
- 在浏览器从 records/aggregate 派生 ECharts option；
- 自动把 content 视为安全 inline；
- 让模型构造文件路径、签名 URL、完整 source 或物理 binding；
- 把 preview、model sample 或 viewport 数量冒充完整结果；
- 复制实现到 runtime-ui。

验证门禁：

- clientToolContract.test.ts 与 clientToolDefinition.type-test.ts；
- 大结果、空结果、安全 inline、超限 preview、取消、上传失败和幂等补偿测试；
- binding identity、range、ordering、数量与 partial 语义回归；
- renderer 测试证明前端只消费 canonical source；
- iot-ui 等 owning module 的窄构建；
- git diff --check 与旧 presentation adapter/场景特调扫描。

历史交付：统一大结果与补偿边界已由 PR #99 合并；浏览器 presentation 写路径由 PR #98 删除。具体测试数量、覆盖率和构建日志以 PR/CI 为准，不在本规范重复保存。
