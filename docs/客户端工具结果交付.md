# 客户端工具结果交付

## 当前结论

客户端工具的大结果和 renderer-ready 结果统一经过 `jetlinks-web-core` 的结果交付边界，不再由业务工具各自判断是否上传文件、拼接路径或组装
evidence。交付策略固定为 `session-file → explicit safe inline → bounded preview`：能安全写入会话文件时交付完整 artifact；文件能力不可用、
上传失败或完整文件超过文件上限时，只有 producer 显式声明且未超过字节上限的安全 inline source 才能完整交付；否则仅使用 producer 的 preview。

该契约解决同一 `call.id` 在不同对话或不同轮次中重复使用导致文件覆盖的问题，同时保证关闭文件能力后，模型仍可通过 canonical binding
产出结构化内容块。它是通用客户端工具交付能力，不按工具名、renderer、页面或业务字段特调。

## 影响范围与 owning module

- owning module：`ui/jetlinks-web-core`
- 主要入口：`src/layout/components/AiChat/clientToolResultDelivery.ts`
- 业务接入方：运营端各模块通过通用描述符声明 artifact；业务模块不再直接调用 `sessionFiles.upload`
- 后端配套：`modules/jetlinks-ai-agent` 只负责 runtime source ledger、模型可见投影和 canonical presentation block 物化

## 统一制图责任边界（2026-08）

### 目标与 owning module

## 工具输入默认值契约

`AiClientToolInput.defaultValue` 是与模型供应商无关的输入契约。`clientToolRouting.ts` 在建立会话工具目录时，统一把它投影为
JetLinks `PropertyMetadata.expands.default`；后端先生成 canonical schema，再由模型 provider 方言适配器处理具体请求格式。
业务工具不声明 OpenAI JSON Schema，执行层仍必须使用同一业务常量做最终默认和范围校验，避免元数据与实际调用漂移。

## 统一结果契约

现有 `AiClientToolRecordStream` 继续处理记录流。新增中性的 `AiClientToolArtifact`，用于描述一个已经由 producer 准备好的 renderer source：

| 字段 | 语义 |
| --- | --- |
| `content` | 完整 artifact 内容；只写 session file，永不自动进入模型结果 |
| `mediaType` / `fileExtension` | 媒体类型与安全扩展名 |
| `outputShape` / `bindingName` | canonical output binding，不由交付层猜测 |
| `recordCount` | 完整结果数量口径 |
| `totalCount` / `displayedCount` | 已知总量与实际 partial source 数量；完整 source 不声明 `displayedCount` |
| `modelPreviewCount` | 模型安全样本数量，只进入不可见的 `modelSample`，不进入用户事实 |
| `maxBytes` | session-file 内容上限 |
| `modelSafeInline` / `maxInlineBytes` | producer 审核过的 JSON source 及其 inline 上限；不声明则禁止完整 inline |
| `preview` | producer 显式生成的有界预览 |

交付层只处理通用生命周期，不读取领域字段来裁剪 JSON，也不根据 renderer 类型生成 preview。producer 对 content、outputShape、数量和 preview
正确性负责；交付层对序列化、容量、路径、上传、取消、失败清理和 canonical evidence/output binding 装配负责。

### 数量语义与事实可见性

数量必须描述其所属层级，不能把模型安全采样、完整 artifact 和用户可见 presentation 混成一组无语义数字：

交付层已把完整 source、partial source 与模型安全样本拆成独立口径。完整结果不再把 preview 长度写入 `displayedCount/returnedCount`；修复落在
统一 artifact/evidence 契约，不在文搜图 renderer 或终答文案中增加特判。

| 字段 | 语义与使用边界 |
| --- | --- |
| `recordCount` | 完整 artifact 实际包含的记录数 |
| `totalCount` | 当前工具查询范围内已知的结果总数；未知时不猜测 |
| `returnedCount` | producer 实际返回并成功交付给 downstream source 的记录数 |
| `displayedCount` | 仅当交付的 presentation source 本身是部分结果时出现 |
| `modelPreviewCount` | 仅供模型观察的内部安全样本数，不进入用户 claim、summary 或事实审计 |

完整 session-file 或 safe inline source 包含 12 条、模型只观察 5 条 preview 时，用户可见契约是
`recordCount=12, returnedCount=12, totalCount=12, complete=true, truncated=false`；`modelPreviewCount=5` 只属于内部投影，不能生成
“已展示前 5 张”等用户事实。只有 source 确实降级为 5 条 partial 结果时，才使用
`totalCount=12, displayedCount=5, complete=false, truncated=true` 并向用户披露 `5/12`。前端分页、虚拟滚动或当前 viewport 数量只是展示状态，
不回写为 source 的 `displayedCount`。

工具结果继续按以下四类信息分责：

- `userClaims`：数量、时间范围、完成状态等可进入用户回答和事实审计的权威事实。
- `resources`：供 runtime 物化的 opaque resource descriptor，不暴露物理路径或签名 URL。
- `modelSample`：帮助模型理解结构的有界样本，只能用于组织表达，不能自动升级为用户事实或 downstream source。
- `runtimeDiagnostics`：阈值、截断原因、投影限制和传输状态，只用于诊断与降级决策。

旧历史继续由 read adapter 只读兼容；同一未发布变更中的中间数量字段直接收敛为上述语义，不新增双写或按 renderer 修正数字的兼容分支。

### presentation 叙事策略

renderer 可在通用 capability 中声明 `contentResponsibilities`、`affordances` 和 `narrativePolicy`。策略只指导模型组织正文，不改变授权、工具可达性、
presentation 是否完成或任务终态：

| `narrativePolicy.mode` | 默认正文职责 |
| --- | --- |
| `card-first` | 卡片已承载明细与操作时，只保留摘要和可选下一步；默认最多 2 个文本块、300 字符 |
| `analysis` | 允许基于证据解释趋势、比较和异常；默认最多 4 个文本块、1200 字符 |
| `free` | 无卡片内容职责时保持普通正文组织；默认最多 8 个文本块、4000 字符 |

声明 `contentResponsibilities` 而未显式选择模式时默认 `card-first`；未声明卡片职责时默认 `free`。ECharts 等需要解释数据关系的 renderer 显式使用
`analysis`。前后端只接受低基数 token 和有界数值，超界输入统一归一化；这些上限不参与任务完成校验，runtime 也不改写模型正文。

## 交付与生命周期

1. 会话文件可用且完整 source 未超过文件上限时，优先写入 session file，并返回 `fs://` binding。
2. 文件能力关闭、不可用、上传失败或完整内容超过文件上限时，仅当 `modelSafeInline` 可 JSON 序列化且未超过 `maxInlineBytes`，才返回
   `data.presentationSource` 与 `$.data.presentationSource` binding。交付层不会把 `content` 自动视为安全 inline。
3. 未声明安全 inline、序列化失败或超过 inline 上限时，只使用 producer 提供的 preview，并生成 partial evidence；preview 不会自动升级成
   downstream source。没有安全 preview 时仅返回有界 summary 与 warning。
4. 默认文件名由稳定工具段、可读时间和每次执行生成的 execution UUID 组成。`call.id` 只承担调用关联，不能作为跨 turn 唯一文件名；
   同一执行的分块写入复用同一路径，不同执行永不覆盖。
5. 上传取消或失败时清理本次未完成产物，不删除历史成功产物；错误局部降级，不能让已经成功的业务查询整体失败。

### 幂等补偿与空结果契约

文件删除区分两种语义，不能通过隐藏 `404` 或扩大空 `catch` 混为一谈：

- 用户主动删除保持严格语义，目标不存在时返回 `404`，用于暴露过期状态和错误操作。
- 交付失败或取消后的补偿删除使用 `ignoreMissing=true`；目标已由服务端回滚或其他补偿请求删除时视为成功，但权限、非法路径和存储错误仍正常传播。

客户端交付不再用 `writeAttempted` 猜测文件状态，而是维护 `not-started / unknown / opened / committed / rolled-back`
状态：请求发出但尚未确认时为 `unknown`，分片成功后为 `opened`，交付结果完成装配后才进入 `committed`；仅 `unknown/opened`
允许调用幂等补偿删除。服务端 `FileDeleteOptions` 和 HTTP 删除接口承载统一 `ignoreMissing` 契约，用户文件管理入口继续使用默认严格删除。

记录流成功完成且 `count=0` 时直接返回完整的 empty evidence：不上传空 NDJSON、不产生文件 binding，也不发起补偿删除；该结果不标记为
`fileUnavailable`，避免把“确实没有记录”误报成文件能力故障。

测试目标覆盖：严格删除不存在文件仍为 `404`、幂等删除不存在或重复删除成功、选项跨本地/命令/HTTP 边界保真、上传失败和调用方取消只补偿一次且
携带 `ignoreMissing=true`、零记录无上传/删除请求且 empty evidence 完整。实现不新增按设备、工具、renderer 或页面判断。

## 兼容边界与非目标

- 普通 inline 工具结果和 `AiClientToolRecordStream` 的现有行为不变。
- 已持久化的旧 `fs://` 引用继续只读恢复，不迁移、不双写。
- 设备或其他工具显式声明 `writeToPath` 时，其覆盖/追加语义由业务工具拥有，不被默认 artifact materializer 接管。
- 不新增 renderer 专用分支，不让模型构造文件路径、签名 URL、完整 source 或物理 binding。
- 不改变会话文件权限、业务查询接口、检索算法、页面结构或 `runtime-ui`。

## 验收目标

- 相同 `call.id` 的多轮、多会话执行生成不同路径；同一执行的分块写入复用同一路径。
- 文件开启时返回完整且唯一的 `fs://` binding；文件关闭或上传失败时仍返回可渲染的 inline/partial block。
- partial 结果明确完整数量与展示数量，不能作为完整证据参与后续数据推理。
- 完整 12 条结果即使模型安全样本只有 5 条，正文也不得声称“只展示前 5 条”；只有 source 实际 partial 时才披露 `5/12`。
- 模型可见工具消息不包含完整 renderer JSON、图片签名 URL 或物理文件路径。
- 取消和上传失败不留下半成品，不覆盖历史 artifact，也不改变普通 inline、record stream 与显式 `writeToPath` 行为。
