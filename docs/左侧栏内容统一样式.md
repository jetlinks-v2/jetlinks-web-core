# 左侧栏内容统一样式

## 1. 目标与当前结论

把 7 个运行时页面左侧内容区统一为同一种「标题/分段器 → 搜索 → 内容 → 底部新增按钮」结构，参考图见 `runtime-ui/参考图片/`：

- `Sidebar-6-空间列表.webp`：无分段器，顶部保留标题
- `Sidebar-5-按设备按空间.webp`：有分段器，顶部不出现标题

设备范围树采用根节点原行搜索及底部单一滚动视口。经浏览器评审，方案调整为名称省略并提供全文提示、计数徽标紧随名称，悬停/聚焦时原位替换为无独立灰底的更多按钮；仅深层缩进超过可用宽度时横向滚动，避免名称从固定数量列下面穿过。连线与缩进直接复用 Ant Tree 原生实现，不再手绘，组件通过原生样式前缀隔离历史全局覆盖。此处的新契约优先于下方原始页面统一步骤。空间与分组共用该结构，其他页面不随之自动迁移。

统一契约：

| 规则 | 结论 |
| --- | --- |
| 标题 | 左侧栏有分段器时不渲染标题；无分段器时保留标题 |
| 搜索框 | 统一使用 `a-input`，左侧 `#prefix` 插槽固定放 `icon-gaojingzhongxin-zhinengsousuo-sousuo` |
| 新增按钮 | 存在时统一下沉到左侧栏底部，`block` 撑满，默认按钮样式（不再用 primary/dashed/自定义蓝色） |
| 间距 | 标题/分段器、搜索框、内容区、新增按钮之间统一 `gap: var(--space-4)`（16px） |
| 内边距 | 子元素不再各自设置纵向 padding，纵向间距全部由容器 `gap` 提供 |
| 树的活动行 | 无连线 Tree 的键盘焦点框统一绘制在整行内部；避免内容区焦点框被行裁剪成两条竖线，目录浮层也沿用此规则 |

## 3. 明确不做

- 不修改任何接口、查询参数、权限、i18n 文案和业务事件。
- 不向其他页面扩展搜索功能；设备范围树已支持根节点原行搜索，后续公共化边界见第 7 节。
- 不改分段器本身的样式与选项文案。
- 不处理页面级 `padding` 归零（`getContentPanelOverrides()` 里的 `padding` / 面板内边距），本次按用户要求「先不管」，与 `jetlinks-web-core/docs/页面内容面板与页面头部插槽.md` 的迁移分开推进。
- 不改 `ui/`（运营端）。

## 4. 实施要点

1. **空间配置**：`AreaTreePanel` 的搜索前缀图标换成统一图标；面板改为 `gap: var(--space-4)` + `padding: 0 var(--space-4)`，标题头去掉 `40px` 固定高度与下边框，搜索/树/底部按钮不再各自带纵向 padding。
2. **产品列表**：`ProductCategoryTree` 补标题「产品分类」（复用既有 i18n key `Product.index.660348-36`），栅格布局改为 flex 纵向 + `gap: var(--space-4)`，内容区 `flex: 1`，新增分类按钮改为默认 `block` 按钮。
3. **设备列表**：`IotDeviceScopeSidebar` 只把 `--space-3/--space-2` 间距统一为 `--space-4`，新增分组按钮去掉 `type="dashed"`。
4. **视频列表**：`MediaDeviceTree` 搜索前缀由可点击 `button + SearchOutlined` 改为统一图标（搜索仍由 `update:value` / `press-enter` 触发），并删除随之失效的 `.mdt__search-action` 样式。
5. **分屏播放**：`VideoMonitorWallSidebar` 统一搜索图标；底部按钮改用 `#icon` 插槽、去掉自定义蓝色按钮样式；`.vmw-sidebar__footer` 去掉 `padding-top`，间距交给 `gap`。
6. **目录管理**：`Catalog/Left` 把 `a-input-search` 换成带前缀图标的 `a-input`，新增按钮从搜索框下方移动到左栏底部，树区域改为 `flex: 1` 滚动、空态居中。
7. **物联告警**：左栏搜索换成带前缀图标的 `a-input`，左右两栏 `gap` 统一为 `--space-4`，标题字重统一为 `600`，新增规则按钮去掉自定义高度/圆角。

## 7. 通用目录树封装

目标：把已经验证的树呈现与搜索交互收敛到 core 公共组件，设备页只保留业务范围和动作。公共组件 API 与设备侧消费者迁移的方案已确认，按下述边界实施。

### 范围与契约

- owning module：`jetlinks-web-core/src/components/NavigationTree/`，从 core 组件入口导出并注册；首个消费者为 `device-manager-ui/views/device/list/components/IotDeviceScopeSidebar.vue`。
- 新增 `NavigationTree`，组合 Ant Tree 的公开能力；保持既有 `AutoTree` 的属性、实例和默认虚拟滚动契约。
- 公共部分负责名称省略与全文提示、填满可用高度的单一滚动视口及位于内容区底部的横向滚动条；深层缩进溢出时整行随视口滚动，不再固定数量列。连线、缩进和展开控件直接复用 Ant Tree，通过其原生 `prefixCls` 隔离历史几何覆盖，不手绘连线。
- `#title` 提供名称内容，`#node-meta` 提供紧随名称的计数或状态，`#node-suffix` 提供行尾操作；公共组件管理布局，不解释设备数量或内置分组菜单。
- `searchable` 启用树上方的常驻搜索，`searchNodeKey` 标识范围根，`v-model:searchValue` 同步关键词。公共部分负责标准输入框、清空与 Escape、保留匹配祖先、搜索期间临时展开和退出恢复。沿用原有 Tree 选择与展开事件；搜索本身不触发选择。
- 路由、空间/分组切换、快捷范围、API、计数口径、权限、空态管理导航和分组维护继续由设备模块持有。

### 实施步骤

1. 在 core 实现和导出公共组件及必要的搜索 hook，补齐类型、父容器高度约束和插槽说明；按已确认的元信息方案移除固定数量列，长名称省略并提供全文提示。
2. 用当前空间、分组两个消费者接入，移除设备侧被公共组件接管的滚动、固定列及搜索交互重复实现。
3. 用无设备字段的通用目录数据验证公共能力，再集中检查设备侧真实筛选、计数和维护动作。

### 约束与验证

- 本次不批量改产品、视频、空间管理等其他页面，不新增后端接口或依赖，不改变权限和查询含义。
- 当前 Ant 4.x 下自然宽度横向滚动采用原生节点布局；不承诺万级节点全展开性能。已有大规模虚拟树继续使用 AutoTree。
- 验证：公共组件类型与行为回归、设备侧回归、依赖范围生产构建；浏览器覆盖空间/分组、深层长名、底部滚动条、右侧尾列、搜索空态及焦点、宽窄容器。
- 公共组件、搜索/展开状态、首个业务接入及专用类型夹具已实现。公共行为回归 7/7、原 AutoTree 回归 4/4、设备相关回归 25/25 通过；公共组件及九层预览夹具的专用 `vue-tsc` 通过。设备与规则模块依赖范围生产构建成功（最新布局对齐构建 1m 2s，保留既有资源引用及大 chunk 警告）。全量设备类型检查仍有 1,764 条既有诊断，归一化后无新增签名；工程没有独立 lint 脚本，改动差异空白检查通过。
- 范围切换布局差异来自快捷项仍按分组维护权限预留空操作列，以及普通计数/按钮分别占用 20px/24px。已删除快捷项的无效操作列，并让计数与绝对定位的维护按钮共用最小 24×24px 单元。浏览器实测两种范围的快捷项列宽均为 `158px 20px`、数量右边界均为 459px，目录元信息均为 24×24px、节点行高均为 28px。回归覆盖空间、可维护分组、无权限分组及关闭维护入口四种状态。
- 浏览器已验证 Ant Tree 独立原生样式前缀生效，没有自绘连线；九层目录在 218px 树视口内内容宽 336px，横滚达到 118px，滚动视口底边与固定底部动作上边均为 549px。拖宽后名称区随之扩大，无名称/数量重叠。真实设备页验证分组选择驱动右侧设备列表、搜索及原生清空保持原 `scopeId`、分组菜单复用计数位置且触发器背景透明；中日文界面已目视复核，短控件继续复用原有 AutoFitText。
- 未执行万级节点全展开性能测试和全工作区生产构建；原 AutoTree 的虚拟滚动用途不变。当前修改未提交或推送。

## 8. 多语言文字适配

当前 core 已公开 `AutoFitText`，由 `useContentFit` 根据实际可用宽度调整 12–14px 字号，并监听容器、文案和字体加载变化。短文案恢复后回到正常字号；达到下限仍溢出时保留完整提示。设备侧的分段标签、快捷项和底部按钮先复用这项能力，不新建文字测量工具。

- 分段器和受限按钮：先保证可伸缩容器和图标固定空间，文字在有界范围内适配，保留完整可访问名称。
- `SlantedTabs`：已有基于选项、插槽内容和容器变化的重新测量及溢出菜单，继续采用导航溢出机制，不统一缩小所有页签。
- 搜索：短占位文案、完整作用范围的可访问名称和原生清空按钮，多语言不通过压缩录入文字字号解决。
- 树和表格内的对象名称：保留正常字号，采用适合内容的横向滚动或完整查看入口。

设备侧短控件继续复用上述既有能力。全站基础控件和其他业务页面的批量迁移另按真实溢出样例推进，不以语言代码设置固定字号，也不全局缩小正文、数字或用户输入。

## 9. 深层目录与右侧数据的设计契约

初始只展示两层业务节点：展开首层业务分支，第二层可见但其子级默认收起；“全部空间 / 全部分组”属于范围根，不计业务层级。这是本场景的初始策略，不是设计系统规定的通用深度上限。已有选中项的祖先路径及搜索匹配路径允许展开到更深层；退出搜索恢复原展开状态，计数刷新、多语言切换不重新折叠用户已展开的分支。

默认展开及选中路径揭示由 core `NavigationTree/useNavigationTree.ts` 持有。设备 hook `views/device/list/hooks/useIotDeviceScopeSidebar.ts` 只分别记忆空间、分组的受控展开状态，不重复制造默认展开真值。

| 使用场景 | 呈现与职责 |
| --- | --- |
| 窄侧栏的目录导航 | 名称、贴近的次要数量、原位替换数量的维护菜单；使用 Ant Tree 原生缩进和连线，长名称省略并提供全文提示，仅深层缩进超宽时在底部单一视口中横向滚动 |
| 目录选择驱动右侧列表 | 树负责选择范围；复杂状态、时间和其他字段由右侧表格展示。深层选中项的路径可回显在既有筛选区，作为后续独立接入点，不自动增加新的工具栏行 |
| 每个层级节点都需要比较多列数据 | 使用内容区的树表格并遵循 treegrid 的行/单元格键盘契约；不把 NavigationTree 扩成一套表格框架 |

成熟设计依据：

- [Fluent Tree](https://fluent2.microsoft.design/components/web/react/core/tree/usage)：导航模式通过展开控件控制层级，选择节点在另一表面展示详情；尾部采用简短徽标和少量动作，说明文字与截断后的全文入口需要可理解。
- [Carbon Tree view](https://www.carbondesignsystem.com/building-blocks/core/components/tree-view/guidelines)：默认32px行高，复杂嵌套可采用24px紧凑行；保持节点对齐、完整查看途径和折叠后选中上下文。当前页面使用 Ant Tree 的原生几何，不为深层数据无限缩小字号。
- [W3C Treegrid](https://www.w3.org/WAI/ARIA/apg/patterns/treegrid/)：需要操作或比较多列层级数据时，显式使用树表格及相应键盘导航语义。

## 10. 可编辑树交互补全计划（M，已确认）

目标：让具备维护权限的目录树支持右键菜单、持久化同级排序及跨父级移动，并明确区分顶级新增与子级新增。当前底部 `create-group` 已通过 `useIotDeviceGroupManagement.openCreateGroup()` 创建无 `parentId` 的顶级分组，需修正入口表达，不把它改成隐式依赖选中节点。

### 范围与边界

- 公共呈现 owner：`jetlinks-web-core/src/components/NavigationTree/`，复用 Ant Tree / Dropdown 的原生右键与拖动能力，右键和更多按钮消费同一份节点菜单定义。
- 首个可编辑消费者：`device-manager-ui/views/device/list/components/IotDeviceScopeSidebar.vue`、`hooks/useIotDeviceGroupManagement.ts` 及两个现有设备列表宿主。菜单、权限、保存和错误反馈继续由设备模块持有。
- 排序使用现有 `DeviceGroup.sortIndex` 与资产权限 CRUD 保存能力；核对批量保存和失败行为，不用前端并发逐个更新模拟批量成功。
- 已确认支持同级排序、跨父级移动及移至顶级；使用 Ant Design Vue 4.2.6 官方拖动示例的落点语义，不新增拖拽库。不修改空间导航的只读定位，不批量迁移产品、视频或空间配置树，不修改运营端 `ui/`。

### 实施步骤

1. 提供可选节点菜单入口，复用已有新增子分组、编辑、删除行为；节点右键不改变右侧设备筛选。保留更多按钮和键盘可访问入口，避免只提供鼠标右键。
2. 根节点及目录空白处的右键菜单提供“新增顶级分组”；底部新增按钮使用同一明确文案。子节点菜单的新增动作明确标识为“新增子分组”，继续使用同一编辑对话框并显示目标层级。
3. 在可维护且未搜索时启用原生拖动；节点内落下改变父级，前后插入改变兄弟顺序，拖入合成根移至顶级。禁止拖动合成根和快捷范围、拖入自身及后代，保存期间禁止重复拖动。批量保存 `parentId` / `sortIndex` 后重新读取服务端顺序；失败提示并恢复服务端状态，保持选中范围和展开偏好。父级与后代路径维护、整批事务及资产权限复用现有框架契约。

### 滚动与数据加载契约

- 首批请求一个有界批次；接近内容底部时再取下一批，无页码、跳页和每页条数控件。批次大小为内部加载参数，建议从 50 开始，结合真实首屏与补齐请求验证。
- 复用现有 `queryDevicePage_api`（`POST /device/instance/detail/_query`）作为批次传输，保持 `createTime desc, id asc` 排序、类型和权限条件；当前 API 没有已核验的列表游标/逐条流式读取入口。本方案的“流式”指滚动渐进取数与显示，当前不新建后端推送协议。
- 加载状态分开：首批骨架、追加 loading、首批 error、追加 error、hasMore。追加失败保留已加载行与选择，在底部就地重试；用户可通过“继续加载”完成同样操作。首屏未填满且仍有后续时继续按批补足视口。
- 同一时刻只允许一个追加请求；类型、范围、状态、搜索改变后生成新的查询版本，回到顶部并加载首批。旧响应以及旧运行态补齐均不能写入新版本；组件卸载清理请求和监听。查询失败与已加载完毕具有不同表达。
- 成功后才推进下一批位置，按稳定 id 合并并避免重复；已有分页接口在并发增删时不提供严格快照一致性，去重不能解决全部偏移跳漏，主动刷新会重建当前结果。本轮不承诺游标快照语义。
- 总数与状态统计独立管理，统计失败不清空列表；列表分页接口自身携带 total 的计算成本需要实测，不能把“隐藏分页器”写成无 count 查询。
