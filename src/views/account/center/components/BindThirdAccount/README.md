# 当前用户单点登录绑定

单点登录列表与基本信息中的绑定摘要读取 `/application/sso/me/bindings`，以接口的 `bound` 字段展示当前用户的第三方账号绑定状态。`bindTime` 是绑定时间，不代表登录时间；登录历史属于安全设置。

应用带有 `ssoUnsupportedRedirect` 只表示不能使用网页重定向绑定，不应被过滤：接口返回的已绑定和未绑定入口均展示真实状态；尚未绑定且页面没有可用绑定流程的入口显示禁用操作及原因。微信和钉钉的已有扫码绑定流程继续使用。

后端先从应用管理器取得已启用且具有单点登录能力的应用，再查询当前用户绑定。已停用或未加载的应用不会通过该接口返回，即使历史绑定仍存在；空列表不能证明账号从未绑定。

列表上方的提示说明绑定后的登录方式；按现有布局端类型判断，运营端指引管理员到“系统管理 > 应用管理”，项目端沿用“开放与集成 > 第三方登录”。

实现入口：useSsoBindings.ts 管理列表与绑定交互，../../useCenter.ts 构造基本信息摘要；两处均保留接口返回的数据。ssoBindingCapability.ts 判断是否可在本页面发起绑定。接口仍由后端按照当前认证用户查询。

验证：两个个人中心定向测试文件共 35 项通过，覆盖绑定状态、空结果、查询失败和扫码绑定等；单点登录组件脚本、模板、样式及中英文文案解析通过。测试使用接口替身，真实登录态与实际绑定流程仍需核对；未执行全量构建。

当接口真实返回空数组时，CloudEmpty 使用同一端类型判断提示配置路径及启用状态；查询失败保留错误提示和重试，不将失败解释为系统未开放。
